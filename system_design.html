二、数据库设计 (SQL DDL)

2.1 设计要点

  • 自关联设计：performance_kpi.parent_kpi_id 和 performance_task.parent_task_id 均为自引用外键，二级部门指标 parent_id = NULL，三级部门指标 parent_id = 对应二级指标ID
  • Excel追溯字段：每条记录保留 excel_row_ref（原始行号）、excel_merge_range（合并单元格范围）、source_type（excel/manual）、excel_file_name，支持覆盖更新时精准定位
  • 里程碑独立表：performance_milestone 通过 task_id 外键关联重点工作，支持 H1/H2 两种类型，key_tasks 以 JSONB 存储关键任务列表
  • 权重校验：check_weight_total() 函数实时校验某部门KPI+重点工作权重是否=100%
  • 部门自关联树：department 表通过 parent_dept_id 自关联，dept_level 字段区分二级(2)/三级(3)

2.2 核心表结构

表名用途关键字段关联关系
department 部门表 dept_code, dept_name, dept_level, parent_dept_id 自关联树 (二级->三级)

2.3 自关联设计详解

核心思路：同一张表存储二级和三级部门的指标，通过 parent_kpi_id / parent_task_id 建立父子关系：

-- 二级部门KPI: parent_kpi_id = NULL (根节点)
INSERT INTO performance_kpi (id, dept_id, parent_kpi_id, indicator_name, weight, ...)
VALUES ('k1-l2', 'dept-l2', NULL, '大版本节点达成率', 0.10, ...);

-- 三级部门KPI: parent_kpi_id 指向二级部门KPI (子节点)
INSERT INTO performance_kpi (id, dept_id, parent_kpi_id, indicator_name, weight, ...)
VALUES ('k1-l3-a', 'dept-l3-a', 'k1-l2', '大版本节点达成率(承接)', 0.10, ...);

-- 查询: 某二级部门KPI被哪些三级部门承接
SELECT k2.indicator_name, d3.dept_name, k3.target_value, k3.completion_rate
FROM performance_kpi k2
LEFT JOIN performance_kpi k3 ON k3.parent_kpi_id = k2.id
LEFT JOIN department d3 ON k3.dept_id = d3.id
WHERE k2.id = 'k1-l2';

优势：无需跨表JOIN即可实现层级查询，支持递归CTE查询任意深度的指标血缘链。

三、Excel解析逻辑 (Python)

3.1 核心挑战：合并单元格处理

Excel中的重点工作板块通常使用合并单元格来表示"一个重点工作对应多个里程碑"的结构：

行号B列 (任务名称)C列 (权重)D列 (H1/H2)E列 (里程碑)F列 (关键任务)
5大版本升级能力建设10%H1完成分支收编策略迭代策略制定
6H1完成升级工程能力规划SCMP整合
7H2支撑榫卯5.0落地分层方案

问题：openpyxl 读取合并单元格时，只有左上角(B5)有值，B6和B7为None。

解决方案：构建合并单元格映射表，子单元格通过映射自动读取左上角的值。

3.3 核心代码逻辑

def _build_merge_map(self):
    """构建合并单元格映射表
    对于合并区域 B5:B7, 建立:
    { (6, 2): (5, 2), (7, 2): (5, 2) }
    子单元格通过映射找到左上角值"""
    merge_map = {}
    for merged_range in self.ws.merged_cells.ranges:
        min_col, min_row, max_col, max_row = range_boundaries(str(merged_range))
        for row in range(min_row, max_row + 1):
            for col in range(min_col, max_col + 1):
                merge_map[(row, col)] = (min_row, min_col)
    return merge_map

def _get_cell_value(self, row, col):
    """获取单元格值, 合并单元格返回左上角值"""
    if (row, col) in self._merge_map:
        top_row, top_col = self._merge_map[(row, col)]
        return self.ws.cell(row=top_row, column=top_col).value
    return self.ws.cell(row=row, column=col).value

def _parse_task_section(self, section):
    """解析重点工作板块 - 处理合并单元格"""
    tasks = []
    for row in range(data_start, max_row + 1):
        if row in processed_rows:
            continue

        # 读取任务名称 (合并单元格自动返回左上角值)
        task_name = str(self._get_cell_value(row, task_name_col) or "").strip()

        # 检测合并范围
        merge_range = self._get_merge_range_str(row, task_name_col)
        if merge_range:
            min_col, min_row, max_col, max_row = range_boundaries(merge_range)
            merged_row_count = max_row - min_row + 1
        else:
            min_row = max_row = row
            merged_row_count = 1

        # 创建重点工作对象, 从合并区域第一行读取主体字段
        task = TaskRow(task_name=task_name, excel_row_ref=row,
                         excel_merge_range=merge_range)
        task.weight = self._parse_weight(str(self._get_cell_value(row, weight_col)))

        # 遍历合并范围内的每一行 -> 每行是一个里程碑
        for sub_row in range(min_row, max_row + 1):
            processed_rows.add(sub_row)
            milestone = MilestoneRow(excel_row_ref=sub_row)
            milestone.milestone_type = str(self._get_cell_value(sub_row, ms_type_col) or "").strip()
            milestone.milestone_name = str(self._get_cell_value(sub_row, ms_name_col) or "").strip()
            # 关键任务按换行符/分号拆分
            kt_val = str(self._get_cell_value(sub_row, kt_col) or "").strip()
            milestone.key_tasks = [t.strip() for t in re.split(r'[\n;；•·]+', kt_val) if t.strip()]
            task.milestones.append(milestone)

        tasks.append(task)
    return tasks

3.4 刷新规则：覆盖更新 vs 增量更新

模式说明适用场景数据安全性
覆盖更新 清除该部门该年度所有Excel来源的数据，重新写入。手动添加的数据可通过source_type='manual'保留 年度目标重新设定、大规模调整 中 (会清除旧数据)
增量更新 按(dept_id, fiscal_year, indicator_name)唯一键匹配，存在则更新，不存在则新增。通过file_hash跳过重复文件 日常修改、局部调整 高 (保留已有数据)
权重校验时机：每次解析完成后自动计算 weight_kpi_total + weight_task_total，如果不等于1.00(100%)，在excel_upload_batch.weight_valid标记为FALSE，并返回警告信息。

四、跨层级联动与承接 (1对多)

4.1 承接机制设计

核心规则：三级部门在制定绩效时，其KPI和重点工作的选项池必须来源于所属的二级部门。三级部门只能从二级部门的指标中进行勾选或引用（承接）。

承接流程

  1. 二级部门设定目标：二级部门负责人上传Excel，系统解析为KPI和重点工作，存入数据库（parent_kpi_id = NULL）
  2. 三级部门查看选项池：三级部门负责人登录后，系统根据dept.parent_dept_id查询其所属二级部门的所有KPI和重点工作，作为"可承接指标列表"
  3. 三级部门勾选承接：三级部门从选项池中勾选需要承接的指标，系统创建新的KPI/Task记录，parent_kpi_id / parent_task_id 指向二级部门指标
  4. 设置承接目标值：三级部门可在二级部门目标值基础上调整自己的目标值（如二级目标80%，三级可设82%）
  5. 里程碑拆解：对于重点工作，三级部门可对H1/H2里程碑进行进一步拆解，添加自己的关键任务

4.2 数据映射与血缘追溯

-- 查询: 某二级部门的KPI被哪些三级部门承接 (数据血缘)
WITH RECURSIVE kpi_tree AS (
    SELECT id, dept_id, parent_kpi_id, indicator_name, 0 AS depth
    FROM performance_kpi
    WHERE dept_id = 'dept-l2-001' AND parent_kpi_id IS NULL

    UNION ALL

    SELECT k.id, k.dept_id, k.parent_kpi_id, k.indicator_name, t.depth + 1
    FROM performance_kpi k
    JOIN kpi_tree t ON k.parent_kpi_id = t.id
)
SELECT
    t.indicator_name,
    d.dept_name,
    d.dept_level,
    t.depth,
    k.target_value,
    k.completion_rate
FROM kpi_tree t
JOIN department d ON t.dept_id = d.id
LEFT JOIN performance_kpi k ON t.id = k.id
ORDER BY t.depth, t.indicator_name;

5.3 关键信息展示规则

  • 承接状态色标：绿色=已完成，橙色=进行中，红色=待启动/未承接
  • 进度条：每个三级部门承接项显示当前完成率进度条，颜色与状态一致
  • 里程碑展开：重点工作以树状结构展示H1/H2里程碑，每个里程碑节点显示"哪些三级部门在执行"及其进度
  • 覆盖率总览：页面底部显示"X/N 指标已承接 (XX%)"，未承接项数量标红提醒
  • 权重校验：右上角实时显示权重合计是否=100%，不通过时标橙色警告
